## Project Overview

This is a **Tauri desktop application** (芃麦印刷/Pengmai Printing) that wraps a remote web application in a native window. The app is built with Rust backend and vanilla HTML/JavaScript frontend, designed for Windows, Linux, and macOS.

### Core Architecture

- **Hybrid Architecture**: The main window loads a remote web application (`http://110.42.239.85:5000` in production) via Tauri's `WebviewUrl::External`
- **System Integration**: Provides native system notifications, tray icon functionality, and window management
- **Auto Update**: Self-updates via official `tauri-plugin-updater`, driven entirely in Rust (no remote-frontend involvement)
- **Cross-Platform Notifications**: Custom notification implementation with platform-specific approaches:
  - **Linux/Windows**: Uses `notify-rust` directly for better control over notification click handling
  - **macOS**: Uses `tauri-plugin-notification` (stable behavior on that platform)

### Key Technical Details

**Remote Content Security**: Since the main window loads external URLs, the app uses Tauri's capability system (ACL) to explicitly allow frontend commands. The custom `notify` command must be defined in both:
- `src-tauri/build.rs` - generates command ACL permissions
- `src-tauri/capabilities/default.json` - grants permissions to specific remote URLs

**Windows AppUserModelID**: Critical for notification click handling - the process-level AUMID must be set before Tauri plugins initialize to ensure notification clicks activate the correct window.

**Main Thread Window Operations**: Window restoration after notification clicks must execute on the main thread (especially on Windows) via `run_on_main_thread`.

## Project Structure

- **`src-tauri/src/lib.rs`** - Main Tauri application logic, custom commands, notification handling
- **`src-tauri/src/main.rs`** - Entry point with Windows-specific AUMID setup
- **`src-tauri/build.rs`** - Build script that generates ACL permissions for custom commands
- **`src-tauri/tauri.conf.json`** - Tauri configuration (app metadata, window settings, build targets)
- **`src-tauri/capabilities/default.json`** - ACL permissions for remote URLs
- **`src-tauri/permissions/autogenerated/notify.toml`** - Auto-generated permissions for the `notify` command
- **`.github/scripts/publish_updater.py`** - Uploads updater artifacts + emits `latest.json` to MinIO (release.yml)
- **`src/index.html`** - Minimal frontend that demonstrates notification functionality
- **`package.json`** - Node.js dependencies and Tauri CLI setup

## Important Development Notes

### Custom Commands
When adding new Tauri commands that need to be accessible from the remote frontend:
1. Add the command function in `src-tauri/src/lib.rs` with `#[tauri::command]`
2. Register it in `invoke_handler` with `tauri::generate_handler![your_command]`
3. Add the command name to `src-tauri/build.rs` in the `commands(&["your_command"])` array
4. Add corresponding permission to `src-tauri/capabilities/default.json`

### Frontend URL Configuration
The production frontend URL is configured in `src-tauri/src/lib.rs` (line 170-171). For local development, set the `PENGMAI_FRONTEND_URL` environment variable.

### Notification System
The app implements a custom notification flow:
1. Frontend calls `invoke('notify', {title, body, id})`
2. Backend handles platform-specific notification sending
3. Notification clicks restore the window and emit `notification:action` event
4. Frontend can listen for this event to handle navigation

### Window Management
- Window close attempts trigger a dialog asking whether to minimize to tray or exit
- Tray icon provides quick access and quit functionality
- Left-click on tray icon restores and focuses the main window

## Auto Update (MinIO/S3)

The shell self-updates via official `tauri-plugin-updater`, fully driven in Rust (`src-tauri/src/lib.rs`):

- On release builds it auto-checks ~8s after launch; tray menu「检查更新…」triggers a manual check. If a newer version is found, a native confirm dialog appears, then it downloads and installs automatically. Windows NSIS runs passive (`plugins.updater.windows.installMode`), macOS/Linux relaunch is handled in code.
- It fetches the static manifest `latest.json` from the https URL in `src-tauri/tauri.conf.json` → `plugins.updater.endpoints`. The public key in `plugins.updater.pubkey` verifies every installer's signature.
- Updater artifacts (installer + matching `.sig`) are produced only because `bundle.createUpdaterArtifacts: true`.

Release artifacts publish to **both** GitHub Releases and a public-read **MinIO/S3** bucket. `.github/workflows/release.yml` builds per-platform on `v*` tags; `.github/scripts/publish_updater.py` uploads installers + writes `latest.json` (boto3, S3 path-style).

Signing:
- One keypair signs all platforms' installers. Private key is never committed — it lives only in GitHub Actions secret `TAURI_SIGNING_PRIVATE_KEY` and a local backup; public key is committed in `tauri.conf.json`. Rotating the key requires re-pointing every installed client, so back it up.
- Required repo secrets/vars are documented at the top of `release.yml`.

## Release Process

1. Bump the version in `src-tauri/Cargo.toml` and `src-tauri/tauri.conf.json` (must exceed what clients currently run), then push a tag:

```bash
git tag v0.3.1
git push origin v0.3.1
```

2. GitHub Actions builds Windows/Linux/macOS, attaches installers to the GitHub Release, and uploads `installer + .sig + latest.json` to MinIO. Installed clients detect and download the update from MinIO on next launch (or via tray「检查更新…」).
